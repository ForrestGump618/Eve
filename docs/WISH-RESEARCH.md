# 许愿式科研

许愿式科研把一句自然语言愿望转成可持续推进、可检查、可中断恢复的科研项目。入口不是一张要求用户先填完所有参数的表格，而是：

> 我想知道这个公开数据集里哪些细胞状态与耐药相关，并设计能独立验证它的实验。

系统不会把这句话直接当成研究结论，也不会只用一个问题清单回复。它先建立项目章程，再由智能体按节点主动盘点资源、查证据、提出假设、预注册分析、执行计算、规划实验与图表。必要时才请求用户补充不可推断的数据或授权。

可以从聊天直接说出愿望，也可以在「科研与证据 → 许愿式科研」新建项目。聊天中 Eve 会先查同一工作区的已有愿望，再决定续做还是立项；界面会显示当前节点、下一行动和真实产物位置。

## 1. 状态机

| 节点 | 产物位置 | 完成条件 |
| --- | --- | --- |
| 愿望章程 | `charter.md` | 目标、边界、成功判据、未知项、停止条件和预算齐全 |
| 资源侦察 | `evidence/scouting.md` | 实际盘点数据、文献、公开资源、工具和运行环境 |
| 证据矩阵 | `evidence/evidence-matrix.md` | 区分支持证据、反证、来源、适用边界和缺口 |
| 可证伪假设 | `analysis/hypotheses.md` | 假设可被哪些观察否定，竞争假设如何区分 |
| 预注册方案 | `experiments/preregistration.md` | 主要终点、对照、统计方法和停止规则先于结果锁定 |
| 数据分析 | `analysis/` | 真实执行代码、版本、日志、结果和阴性结果已落盘 |
| 实验与独立验证 | `experiments/` | 给出实验、外部队列或复现方案；纯计算课题须说明不适用 |
| 图表与证据整合 | `figures/` | Figure 1..N 的证据递进，并存在真实 SVG/PNG/PDF/HTML 图表 |
| 用户复核 | `reports/review.md` | 用户核对证据、局限和未完成项后人工结题 |

`analysis` 与 `experiment_design` 在预注册后可以并行，适合由队长智能体按依赖拆分给持久子智能体。其他节点按依赖解锁，不能跳过证据门禁。

资源侦察、证据矩阵与假设节点会按需加载 `agent4sci-research-ideation`，把领域科学方法和计算/AI方法分别核查，并区分高风险机制方案与文献支持的稳健方案。预注册、分析、实验设计、图表以及连续推进边界会加载 `agent4sci-research-checkpoint`，检查研究漂移、真实资源、日志、失败原因、预算与未完成行动。两项技能改编自 [Agent4Sci](https://github.com/maszhongming/agent4sci) 的 Research 与 Checklist 技能，固定提交为 `74b0e8c4dc55610072bed4326b6bfac24dc77377`，许可证为 Apache-2.0；Eve 版只使用当前注册工具和现有 `RunService`，没有加入小时级后台调度器。

`wish_status` 的每个 `next_actions` 条目携带所需技能名称，连续推进在每次切换节点时重新检索并加载。技能检索返回实际 ID 后再加载，不把名称当成安装 ID。论文的 Skill 2（Experiment）未安装。检查记录写入当前阶段产物，不在主聊天展示逐项清单或原始 JSON。

## 2. 连续推进与恢复

- 界面上的「继续执行下一阶段」在同一个 durable run 中执行当前节点，并要求模型登记后读取 `wish_status`，继续执行已解锁的 agent 节点。
- 这不是第二个后台调度器。若 run 结束、失败或被暂停，下一次启动会从持久化状态和 `next_actions` 继续，不重做已登记阶段。
- 同一阶段正在执行时不能重复启动。旧 run 已失败、取消或中断后，节点会投影为「失败待恢复」，可以重新启动；提交前校验和提交后状态更新使用同一愿望锁。
- 未解决的阻塞项会阻止继续启动和登记节点。已开始的 run 不会仅因为出现 blocker 就被引擎强杀；用户可在任务界面停止，模型收到 blocker 后也应停止并汇总原因。
- run 成功结束不等于阶段已完成。若没有调用 `wish_record`，节点显示「待真实产物」，不能进入后续依赖。

## 3. 工作区

每个愿望都会在所选本地或 SSH 工作区建立独立目录：

```text
research-wishes/<wish_id>/
  data/
  evidence/
    ledger.md
  analysis/
  experiments/
  figures/
  reports/
    progress.md
  provenance/
  README.md
  charter.md
```

项目状态保存在工作区作用域内的 `research_wish` 记录中；大段数据、代码、图表和报告保留在工作区。每个已登记产物都读取真实文件并保存 SHA-256，不会把模型计划或模拟输出自动当成证据。

产物必须属于当前愿望目录，并放入对应阶段的目录。跨愿望路径、`..`、绝对路径和跨阶段文件都会被拒绝。`experiment_design` 可标记 `not_applicable`，但必须写明为什么当前权限或课题不需要湿实验/独立验证。

## 4. 智能体工具

| 工具 | 用途 |
| --- | --- |
| `wish_status` | 恢复愿望、节点、阻塞项和下一最佳行动 |
| `wish_start` | 一句话创建持久项目与工作区骨架 |
| `wish_update` | 写入可验证章程；后续证据出现后禁止静默改目标 |
| `wish_record` | 登记真实产物、摘要和运行标识；依赖与文件哈希独立检查 |
| `wish_block` | 说明无法自行满足的数据、授权或外部条件 |

结题没有模型工具。只有用户在界面中提交复核人、复核说明和明确确认后，`review` 节点才会完成。

## 5. 自主性与权限

- 优先做出可逆、可核验的假设并继续推进，不因一般信息缺口停在开场提问。
- 只对不可推断的授权、关键数据缺失、预算耗尽或不可逆外部副作用请求用户决定。
- 复用现有 `RunService` / durable task engine 执行真实分析和技能；愿望服务只保存项目状态，不创建第二套调度器。
- 团队协作由智能体按依赖自行决定。简单项目直接执行；出现可并行侦察、分析、实验设计和审查时，可由队长建立持久成员并在侧边栏继续对话。
- 所有文件和应用输出遵循当前工作区、权限模式与审批设置。
- 愿望章程中的预算会写入项目文档。当前仍由现有 `RunService` 的回合预算和取消机制负责硬停止；愿望预算本身不另建执行器。超预算、不可逆操作或权限审批会作为明确的停止原因保留。

## 6. API

所有接口都使用工作区作用域参数 `scope`：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/platform/wishes` | 愿望列表与完整节点状态 |
| `POST` | `/api/platform/wishes` | 创建愿望项目 |
| `GET` | `/api/platform/wishes/{id}` | 单个项目 |
| `PUT` | `/api/platform/wishes/{id}` | 完善章程 |
| `POST` | `/api/platform/wishes/{id}/record` | 登记真实节点产物 |
| `POST` | `/api/platform/wishes/{id}/block` | 建立或解除阻塞 |
| `POST` | `/api/platform/wishes/{id}/review` | 用户人工复核结题 |
| `POST` | `/api/platform/wishes/{id}/launch` | 在当前工作区创建阶段对话；`advance=true` 连续推进，`false` 只做当前节点 |

桌面 Agent adapter 还提供 `wish_status`、`wish_start`、`wish_update`、`wish_record` 和 `wish_block` 工作区操作。

## 7. 边界

- 自动登记证明文件存在、依赖满足和摘要已保存，不证明科学解释一定正确。
- 文献结论仍需原始来源、版本和适用性检查；数据库返回不等于临床结论。
- 人工复核确认的是证据链与交付完整性，不等同于外部科学共同体接受结论。
- 不执行真实分析时，只能报告计划、阻塞或未完成项，不能生成看似真实的结果。
- 连续推进的可靠性由持久状态、工具校验、取消/恢复和回归测试约束；它不保证任何一次模型运行都会自主完成全部阶段。
- Agent4Sci 原文报告的是其自身基准上的结果；技能接入与回归测试通过不等同于 Eve 在真实课题上获得相同提升，也不能排除基准过拟合。
