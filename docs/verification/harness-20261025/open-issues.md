## 仍有产品/架构边界

- 引用验证检查 URL 是否确实来自工具结果，不证明每句话都被来源蕴含；长度要求和所有科研语义没有自动全覆盖。需要领域评审/更强证据蕴含验证。
- 网页搜索目前两家公开 provider；本机 DuckDuckGo 连通性失败，Bing 可用。一些官方网站 Fetch 失败，需要模型改写/切换官方镜像。未集成付费搜索 key 的设置界面。
- Skill 搜索当前是名称/说明的关键词评分，不是 embedding 语义检索。没有一次性注入内容；声明 dependencies 会预检，但没有自动安装依赖。现有科研专家和旧 Skill 页面保留，23 个旧科学 Skill 未全部转为新 manifest.run。
- MCP 当前协议为 2025-03-26；未完整验证新版协商、OAuth、任意服务器长期重连和所有资源/提示词能力。HTTP session 和 stdio 真实工具调用已覆盖。不会因连接健康就宣称工具成功。
- Python Worker 仍是受限环境变量、工作目录、无 shell 的子进程隔离，**不是 OS 安全沙箱**。对声明主机/网络权限的 Skill，普通聊天拒绝自动运行。
- 正式 UI 的专家科研执行仍走原功能路径；默认 lead 聊天才通过统一 Harness Adapter。未宣称所有工作流已统一，也未删除原能力。
- 正式 UI 在流式任务期间仍限制切换会话，避免串话；原生 UI 支持任务流隔离。需要后续实现正式 UI 视图订阅切换与后台运行解耦。
- 长历史采用 80 条窗口及前后导航，未实现任意高度消息的连续滚动虚拟列表。巨量任务快照和超长来源仍需持续容量测试。
- 凭据快照只在内存中；daemon 重启后仍需解锁模型和核查已计费请求。checkpoint 是可诊断恢复证据，不是宣称无损从任意模型 token 自动续跑。
- 安装包未签名；未执行干净 Windows VM 安装/升级/卸载，未验证无 Python 环境、长时运行、断电、休眠或磁盘满。3.3.0 安装包和历史数据保留。
- 打包版默认启动曾有一次 90 秒内没有打开工作台的失败，发生于并行构建/测试期间；完整构建结束后复跑通过 8/8。初始失败保存在 formal-ui-package-rebuild-race.json，原因未完全隔离，不能宣称冷启动零偶发失败。
- npm 全量依赖安装提示 8 项告警；本轮只确认 npm 声明的生产依赖审计为 0。离线 Markdown/图表资源来自开发依赖并随包分发，没有据此宣称整个安装包没有已知漏洞，也没有执行破坏兼容性的自动 force 升级。

固定任务与核心 UI 的验收结果不等于所有产品能力已完善。上述边界继续保留，不能标记“所有请求的 P0 能力全部关闭”或“所有科研工作流均完成验收”。
