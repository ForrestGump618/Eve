## 证据分级

- **确认**：可从发行包的静态代码或包元数据直接读取，且结论不依赖运行未出现的代码路径。
- **推断**：由已确认实现和命名推导出的产品行为，仍需运行时或源码确认。
- **未知**：发行包没有暴露足够证据，或需要真实服务、真实会话与模型交互才能判断。

静态分析能够确认代码中的分支、常量、子进程和 IPC 处理，不能证明真实服务端总会进入这些分支，也不能证明界面上每次操作都呈现相同状态。阈值没有找到时记为“未知”，不以字符串或行为命名代替实现。

## 已确认的运行时行为

| 结论 | 等级 | 证据 |
| --- | --- | --- |
| 每次 `turn.spawn` 都以独立子进程运行，stdout 按行流式回传 | 确认 | daemon `7133-7165`：`spawnTurn` 创建子进程，`turn_stream` 逐行回调 |
| 同一 `sessionId` 启动新轮会先终止该会话旧的轮次 | 确认 | daemon `7133-7136`：遍历活动 `turns`，匹配会话后调用 `killTurn` |
| 取消在 Windows 上终止子进程树，POSIX 先发 `SIGTERM`，3 秒后升级为 `SIGKILL` | 确认 | daemon `7188-7199` |
| daemon 与桌面壳分离；退出桌面壳时，正在执行的轮次子进程刻意不随之终止 | 确认 | ASAR `dist/main.js` 的 `will-quit` 注释与 `stopDaemon` 调用；daemon `7581-7590` 只清理 PTY，不遍历 kill 全部 turns |
| 设备连接使用 500ms 到 15s 的分级随机退避 | 确认 | daemon `7243`、`7314-7319` |
| 下行静默通过 watchdog 检测，静默达到阈值时终止并重连 | 确认 | daemon `7274-7290`、`7334` |
| 连接建立后每 30 秒发送 presence | 确认 | daemon `7242`、`7336` |
| 有结构化的 `RUN_TIMEOUT`、`RUN_STALLED`、`CONTEXT_EXCEEDED` 等客户端错误类别 | 确认 | renderer `ChatMessageParts-*.js` 的错误映射 |
| 回合的子进程运行与桌面窗口生命周期分离 | 确认 | 主进程与 daemon 分离、`turn` 子进程独立于 Electron renderer |

## 静态分析边界

本轮没有把字符串缺失当作 外部项目 一定不存在某功能的证明；只把它作为“无法据此移植固定阈值”的依据。服务端是否另有模型路由、记忆、任务图或硬预算，仍需要对应服务端产物、真实 Trace 或公开源码验证。Eve 因而优先复用已确认的进程隔离、取消、重连和健康监控思路，并用自身可测试的统一 Harness 实现回合治理。
