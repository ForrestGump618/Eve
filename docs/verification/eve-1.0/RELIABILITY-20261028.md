# Eve 1.0.0 可靠性验收 · 2026-10-28

本次修改覆盖技能接入、上下文、运行中输出、供应商模型列表、SSH 凭据和重连、文件差异及桌面交互。源码、解包构建和本机安装版使用同一构建：

`2b43ab1f10d7c315d4287c4127802df09a7c1f89628ee5cfdd67a539af98f51d`

本次不上传 EXE。机器上的配置、历史会话、凭据和个人技能库不进入 Git。原始模型 Trace 留在本机，公开的 [测试矩阵](reliability-20261028.json) 仅保留指标、检查名称和任务结果。

## 根因与修改

| 问题 | 代码路径与实际原因 | 修改与证据 |
| --- | --- | --- |
| 旧版本入口混杂 | 多个旧源码根目录、历史构建和遗留测试进程增加了启动错误版本的可能；这不证明每次旧窗口都由同一个原因引起 | 将旧源码与构建移出工作路径，保留恢复归档；桌面和开始菜单快捷方式指向同一安装版。安装版 E2E 验证只有一个正式窗口 |
| 技能只展示、没有进入运行 | `desktop/scripts/copy-assets.mjs` 没把工作台 Markdown 流程接入原生注册表；选用技能的返回结构还存在数组/对象不匹配 | 27 个流程生成可加载原生技能，与原有 8 项共 35 项幂等注册；输入框选择器最多选择 3 项，由统一 Loop 先加载，再执行工具 |
| 已选长技能丢失 | `desktop/src/context.ts` 将技能指引按普通大工具输出提前归档，模型第一次请求就看不到完整指引 | 为活动技能设置独立阈值；预算足够时保留实际请求。安装版测试检查真实 HTTP 请求确实包含长科研流程指引 |
| 检索反复调用、耗尽预算 | 同一路径对超过 2K 的新检索结果提前压缩，预览只有 160 字符。实测两项任务在反复抓取后触及累计预算 | 默认在完整请求接近硬预算时才剪枝；归档结果保留更有用的首尾摘录和原文引用。相同任务和预算复测 21/22 通过，未再出现预算耗尽 |
| 长对话逐渐膨胀 | 旧派生摘要作为 system 文本反复叠加；显式状态和事实可能非常大；工具 schema 未在最初预留中完整计入 | 替换经过哈希验证的旧派生视图；保留完整本机快照，注入有来源的有界视图。统一核算 messages、schema、输出和安全预留 |
| 小窗口与溢出恢复 | 大工具目录与固定提示可能超过小模型窗口，截断续写也需重新准入 | `<16K` 模型使用简短运行规则和按需 schema；分类识别溢出后最多 3 次缩小有效窗口、重新准入，不重放已执行工具 |
| 执行时一直空白 | `desktop/src/activities/model.ts` 的 40ms 丢帧策略会漏掉工具前最后一个短文本块；正式 UI 没稳定展示该进度 | 去掉丢帧节流，复用已有前端合并渲染；显示中间回复和最近工具状态。安装版在最终响应前断言文本已出现 |
| 同一供应商无法稳定保存多个模型 | 全局默认连接影响其他供应商；未激活供应商的连接信息可能没保存 | `omicslab/config.py` 独立保存地址、首选模型和列表；`provider_models.py` 实际请求列表，限制大小和页数、禁止重定向，失败保留原列表；界面支持勾选、手动添加、首选和保存 |
| SSH 保存后仍要密码 | Windows 运行环境依赖可选凭据包；会话内缓存不等于持久保存 | `omicslab/ssh/windows_credentials.py` 直接适配系统凭据库，支持旧引用迁移。使用实际主机验证独立进程不传密码重新连接 |
| SSH/终端掉线 | 仅依赖传输层默认配置；终端 ready 事件过早重置重试计数可能造成持续重试 | SSH 心跳 15 秒、可用时启用系统 TCP keepalive；终端按 1.5/3/6 秒有限重连，稳定 60 秒后重置；命令不自动重放，连接失败不回退本地 |
| 缺少文件变更交互 | 绑定本地的写入绕过统一适配层，缺少变更记录 | 本地和 SSH 的 `write_file` 走同一后端，写后回读；按工作区、会话、运行记录差异、哈希和前像。输入框上方可查看差异、打开、受保护地恢复旧内容 |
| Windows 偶发启动失败 | 回归测试真实复现 `connection.json` 原子替换被短暂占用，未捕获的 EPERM 导致守护进程退出 | `desktop/src/security.ts` 异步有限重试；保留旧记录，不阻塞事件循环。用真实 Windows 文件共享锁验证释放后发布成功，并通过守护进程强制重启回归 |
| 系统提醒样式不统一 | 已有自定义关闭/安装提示需要在实际安装版确认 | 正式窗口的关闭、取消、托盘、退出确认通过安装版 16 项 E2E；测试拦截验证没有原生 MessageBox。系统文件选择器和 NSIS 安装器不在该结论范围 |

工具、模型、工作区、技能和执行环境仍由现有持久化 Harness 统一调度，没有引入第二个竞争执行循环。文件编辑继续遵循读取哈希与写后核验，权限仍由后端判断。

## 固定真实任务

使用同一个模型 `deepseek-v4.1-flash-economy`，同一份 22 项任务，任务文件 SHA-256：

`08e2cc0eddd7db3d0bd87c4f0027e9825e7fccd0fa1f68a0015f3d4776caf2e6`

每项累计预算 160,000 Token、单步超时 240 秒。任务包括网页检索、PubMed、文献摘要/对比、UniProt、页面读取、授权文件读取、MCP 发现/执行、技能发现/加载/计算及多步骤组合。模型与公开网络调用真实发生；MCP 和均值技能为本地可执行测试服务，不能代表所有外部服务质量。

中间构建的两项失败为官方传输文档检索和搜索后抓取，均实际耗尽累计预算，没有记为成功。最终没有增加预算。最新构建的 `multi-search-fetch` 实际完成检索、读取和引用，但回答使用中文描述，没有包含固定验收要求的 `contextIsolation` 字面关键词，因此仍计为失败，未放宽判定标准。

这是同日各一轮的描述性比较，包含模型随机性与网络变化，并非全部改动之前的完整基线或统计显著性证明。较早的历史矩阵曾记录 22/22、283,308 Token；最终构建并未全面优于该历史记录。引用检查证明可溯源，不证明每句话都被原文支持，尚无全面人工语义评分。

## 仍存在的限制

- 文件变更栏追踪统一 `write_file` 的验证写入，不自动追踪 Shell、Python 或外部程序的任意文件变化；恢复会检查当前哈希，但不提供跨外部进程的事务锁。
- 新建文件不会自动删除；大文件差异预览有截断提示。
- 超大系统规则、单条用户输入或 schema 在保留关键约束后仍无法容纳时，会明确拒绝请求；压缩不能保证任意长度的输入可执行。
- 一项固定任务仍未满足字面关键词质量门禁；引用语义质量、数小时 SSH 长稳、所有第三方供应商列表和每一种专业计算依赖仍未全面验收。
- 系统文件选择器、系统凭据库和已有安装器仍使用各自平台机制；本次没有发布新的 EXE 安装包。
- 旧归档仍占用磁盘；工作集与启动速度需要后续有基线的性能优化。
