# 素问 Suwen — AI Agent 平台升级需求 V2.0

本文件是 V2 的原始需求基线，用于对照验收范围，不随实现回改；当前实现状态见 [SUWEN-V2-CHECKLIST.md](SUWEN-V2-CHECKLIST.md)。

## 一、产品定位

将现有系统升级为一个面向普通用户与科研工作者的可扩展 AI Agent 平台。

核心设计原则：

1. **默认智能化**：普通用户无需理解 Temperature、Token、上下文窗口等技术概念。
2. **高级可配置**：专业用户可以控制模型、工具、Skills、记忆、执行策略及权限。
3. **任务可持续**：支持长时间任务、并行执行、中断恢复和多阶段工作流。
4. **过程透明**：可以观察 Agent 的计划、工具调用、执行过程、错误和结果。
5. **能力可扩展**：兼容 MCP、Skills、消息渠道和第三方服务。
6. **科研专业化**：内置科研 Agent 工作流，支持可验证、可追溯、可复现的研究过程。

产品正式名称为 **素问**，英文名称为 **Suwen**。统一调整 UI、窗口标题、应用图标、文档及对外展示名称，同时保留旧配置与用户数据的迁移兼容性。

## 二、现有 10 项需求的完善

### 1. 模型自动配置与智能路由

- 默认采用智能模式，自动识别模型支持的参数。
- 根据任务类型自动选择模型、推理强度、Temperature 和最大输出 Token。
- 普通用户仅需选择快速、均衡、深度三种模式。
- 高级模式允许分别配置文本、推理、视觉、嵌入和代码模型。
- 支持模型能力探测、连接测试、自动降级与备用模型。
- 根据上下文窗口自动压缩历史信息，避免超限。
- 自动识别不支持的参数，不强行传递 Temperature 等字段。
- 支持按质量、延迟、成本和数据隐私要求选择路由策略。

### 2. 可配置的长期记忆系统

- 支持通过 API 配置独立的 Embedding 模型，也可选择本地嵌入模型。
- 自动将对话、任务结论、用户偏好和项目知识转化为可检索记忆。
- 结合语义检索、关键词检索与重排序实现混合检索。
- 区分短期上下文、长期语义记忆、任务历史和项目知识库。
- 支持自动摘要、记忆合并、冲突检测、过期处理及重新嵌入。
- 提供记忆查看、编辑、删除、导入、导出和暂停记忆功能。
- 支持按工作区隔离记忆，防止不同项目的信息相互污染。
- 记忆写入应有筛选机制，避免将所有聊天内容无差别保存。

### 3. 主动视觉验证与自动修正

- 支持配置独立的视觉模型。
- 生成图片、科研图表、PPT 页面及其他视觉产物后，自动判断是否需要视觉复核。
- 使用视觉模型检查构图、文字错误、遮挡、裁切、布局及与用户需求的一致性。
- 对科研图表额外检查坐标轴、图例、标注以及原始数据与展示结果是否一致。
- 发现可修复问题时，调用对应生成或编辑工具进行修正。
- 设置最大自动修正次数，防止无限循环。
- 支持展示原图、检查报告、修正结果和版本差异。
- 对无法可靠判断的科学事实或图表问题，标记为待人工确认。

### 4. 外部项目 兼容消息渠道系统

- 建立独立的 Channel Adapter 消息适配层。
- 优先支持微信、企业微信、Telegram、飞书、QQ 和 WebChat。
- 通过已有协议或受支持的适配器对接 外部项目 消息渠道插件。
- 提供扫码登录、渠道状态、账户绑定和消息收发测试。
- 支持每个渠道绑定不同 Agent、工作区和权限配置。
- 允许通过聊天消息发起任务、查询进度、接收执行结果。
- 对主动发送、附件、群聊等能力进行渠道级检测，不假设全部平台均支持。
- 默认禁止未经授权的联系人通过聊天消息执行高风险操作。
- 支持渠道独立启停、断线重连、限流、消息去重和错误诊断。

### 5. 品牌统一

- 全面更名为「素问 Suwen」。
- 设计统一的产品名称、图标、启动界面和视觉规范。
- 支持用户自定义 Agent 名称、头像及角色描述。
- 旧数据库、API 配置、Skills 与工作区数据必须保留。

### 6. 多级设置中心

设置页面采用一级侧边导航 + 二级分类 + 内容面板结构。

要求：

- 同一页面可以管理多个相关设置项。
- 支持设置搜索、参数说明、默认值恢复与配置校验。
- 对高级设置提供折叠展示。
- 记录重要配置的修改历史、修改时间与生效状态。
- 支持配置导入、导出、版本回滚和工作区专属配置。
- 设置变更能实时生效的尽量实时生效；需重启的明确提示。

### 7. MCP 服务管理中心

- 支持添加、编辑、删除、启停 MCP Server。
- 支持 stdio、Streamable HTTP 等协议支持的连接方式。
- 支持通过 JSON、表单或配置文件导入。
- 自动发现服务提供的 Tools、Resources 和 Prompts。
- 提供连接测试、工具测试和错误日志。
- 支持 OAuth、API Key 等适用的认证方式及凭据安全存储。
- 可为不同 Agent、工作区分配不同 MCP 权限。
- 支持超时、重试、并发限制与工具调用审批。
- 服务异常时不影响整个 Agent 平台运行。

### 8. 科研 Skills 预装

内置独立的 Scientific Agent 技能分类，重点集成：

**Paper2Agent**
- 论文解析、代码仓库识别和方法提取。
- 将可复现研究方法转换为 MCP 工具与 Skills。
- 支持测试、运行环境检查与结果复现。

**Co-Scientist**
- 研究问题分解。
- 多 Agent 假设生成、批判、排序和进化。
- 支持多轮学术辩论、假设比较和实验设计。
- 标明为基于公开研究的实现，不冒充未开放的原始系统。

**Robin**
- 文献调研、科研假设和实验策略生成。
- 分析实验数据，依据结果迭代科学假设。
- 集成可获得的原始开源组件，提示第三方 API 依赖。

**Empirical Research Assistance**
- 科研代码生成与执行。
- 使用自动评估指标优化计算实验程序。
- 支持候选算法搜索、比较和结果验证。
- 基于公开代码及方法实现，不虚构未公开的能力。

每个技能必须提供来源、安装状态、依赖项、运行要求、版本、权限及示例。

### 9. 高度可定制 UI

- 提供浅色、深色、跟随系统三种主题。
- 支持字体、字号、强调色、界面密度与圆角风格调整。
- 支持布局面板拖动、宽度调整、隐藏和恢复。
- 允许分别展示聊天、文件、任务、工具调用与执行轨迹。
- 支持科研模式、极简模式和开发者模式。
- 支持自定义快捷键、默认首页和工作区布局。
- 流式输出必须保持聊天框和滚动区域稳定，避免界面跳动。
- 保存各工作区的界面布局，支持重置。

### 10. 后端状态及诊断中心

增加始终可访问的「系统诊断」入口。

显示：

- Agent Runtime / Gateway 运行状态。
- 当前工作区与任务执行状态。
- 模型服务连接与响应状态。
- MCP、Skills、消息渠道连接状态。
- 任务队列、并发任务数及异常数量。
- 内存、CPU、存储和可用资源。
- Token 用量、请求耗时、错误率及成本。
- 最近错误日志与执行轨迹。

支持自动健康检查、诊断报告导出、组件级重连，以及明确标注风险的修复操作。

## 三、新增 14 项核心需求

### 11. 持久化任务引擎

建立独立的任务执行系统，不再将任务生命周期完全绑定在聊天窗口上。

- 支持任务创建、排队、运行、暂停、取消和恢复。
- 长任务可以在用户关闭界面后由持续运行的后端继续执行。
- 重要步骤自动保存 Checkpoint。
- 后端重启后可恢复可重试任务。
- 支持父子任务、依赖关系、并行与串行执行。
- 支持失败重试、超时控制和错误分类。
- 不可重复执行的外部操作须有幂等保护。

### 12. 多 Agent 协作与讨论

- 支持创建多个具有独立模型、角色、工具和 Skills 的 Agent。
- 共享指定任务上下文，但默认隔离私人记忆与凭据。
- 支持任务分工、并行研究、交叉审查和结果整合。
- 支持模型之间直接讨论，而不只是分别回答问题。
- 裁判 Agent 负责提出争议和推动收敛，其他 Agent 可以质疑裁判。
- 记录共识、少数意见、未解决问题和结论版本。
- 设置讨论轮次、终止条件和执行预算。
- 最终必须输出明确结论或说明无法达成结论的原因。

### 13. Skills 生命周期管理

- 提供统一 Skill Registry。
- 支持官方技能、社区技能及用户自建技能。
- 支持通过本地目录、Git 仓库及兼容包安装。
- 支持版本升级、固定版本、回滚及卸载。
- 展示每个 Skill 的依赖、调用范围、权限与测试状态。
- 安装前检查来源可信度和潜在风险。
- 支持将多个 Skills 编排为一个复合技能。
- 无法安装或缺少依赖时必须显示真实状态，不允许假装已安装。

### 14. 工具权限与安全沙箱

- 将文件系统、Shell、网络、浏览器、消息发送等能力独立授权。
- 实现只读、需确认、允许执行、禁止使用等权限级别。
- 高风险操作必须审批，包括删除文件、外发敏感数据及修改重要配置。
- 使用隔离执行环境运行不可信代码和第三方技能。
- API 密钥使用安全存储，禁止写入普通执行日志。
- 防御来自网页、文档和工具输出的提示注入。
- 允许随时停止任务、撤销权限和终止执行环境。

### 15. 成本与资源预算管理

- 支持任务级、Agent 级和工作区级预算。
- 分别统计输入、输出、缓存读取、嵌入及其他模型调用费用。
- 支持价格表更新与自定义 API 价格。
- 根据预算自动限制无效重试、过度并行和无意义的长循环。
- 可切换经济模式、性能模式和自定义预算。
- 成本达到预警阈值时提示，达到硬限制时暂停相关任务。
- 输出每次任务的用量与成本估算。

### 16. 科研证据与可复现性管理

- 对重要科学结论记录来源文献、数据或计算结果。
- 明确区分已知证据、推论和待验证假设。
- 支持 DOI、PMID、论文链接及引用管理。
- 分析任务保留代码版本、参数、依赖环境和运行记录。
- 将结果与对应的数据和执行步骤关联。
- 支持科研结果复核、实验版本比较和报告导出。
- 对临床数据提供脱敏检查及外部模型传输限制。

### 17. 可视化工作流编排

- 提供可视化 Workflow Builder。
- 支持模型节点、工具节点、条件判断、循环、并行、人工审批和结果输出。
- 支持自然语言生成工作流初稿。
- 允许保存为模板、复用、导入和导出。
- 展示各节点的运行情况、输入输出和失败原因。
- 可将成熟工作流发布为自定义 Skill。

### 18. 多工作区与项目隔离

- 支持创建独立的工作区、项目和任务集合。
- 工作区分别管理知识库、记忆、模型策略、Skills、MCP 与文件。
- 支持个人工作区和团队共享工作区。
- 提供所有者、管理员、编辑者与只读成员权限。
- 支持项目归档、迁移和恢复。
- 不允许默认跨工作区检索敏感数据。

### 19. 产物与文件管理中心

- 集中管理 Agent 生成的代码、图表、PPT、文档和实验结果。
- 支持文件预览、下载、搜索和版本历史。
- 记录每个产物对应的任务、原始输入和生成过程。
- 支持关联项目文件夹与外部存储。
- 重要文件修改前提供快照或备份机制。
- 支持文件差异查看及恢复历史版本。

### 20. 外部知识源与 RAG

- 支持 PDF、Word、网页、Markdown、代码仓库等知识源。
- 支持本地目录及授权的外部平台数据。
- 提供增量索引、去重、文档版本追踪。
- 检索结果提供原始来源定位。
- 支持多模态资料的解析与索引。
- 允许用户指定某项任务仅使用特定知识库。
- 严格继承知识源的访问权限。

### 21. 配置版本化与迁移

- 配置使用版本化 Schema。
- 支持历史版本回滚和自动迁移。
- 应用升级不得无提示覆盖用户配置。
- 数据库与重要配置支持备份和恢复。
- 插件升级前进行兼容性检查。
- 支持导出脱敏后的配置文件，便于复制到另一台设备。

### 22. 定时任务与事件触发

- 支持定时执行科研检索、汇总和其他自动化任务。
- 支持文件变化、Webhook、消息到达等事件触发。
- 支持任务完成后向已授权的消息渠道发送通知。
- 支持任务失败报警及异常重试。
- 提供自动化任务列表、下一次运行时间、历史记录和停用开关。

### 23. 新用户引导与低门槛交互

- 首次启动提供配置向导。
- 普通用户只需完成模型连接、工作区创建及必要授权。
- 提供预置科研场景和示例任务。
- 高级功能默认折叠，需要时再开放。
- 配置错误时给出具体解决建议。
- 帮助用户理解当前使用的模型、工具和自动化权限。

### 24. 自动评测与回归测试

- 为核心 Agent、MCP、Skills 和消息渠道提供测试用例。
- 支持科研任务的基准测试和结果一致性评估。
- 记录回答质量、工具成功率、执行耗时和成本。
- 每次系统升级执行自动回归测试。
- 对模型更换或 Prompt 更新造成的质量变化提供对比。
- 不允许仅以「模型认为正确」作为自动任务成功的唯一标准。

## 四、建议的系统架构

采用模块化设计，避免将模型、工具、记忆、渠道和界面紧密耦合。

**前端 UI**
- 聊天与工作区
- 任务控制台
- 工作流编辑器
- Skills / MCP / 渠道管理
- 设置与诊断中心

**Agent Runtime**
- 任务规划与状态机
- 多 Agent 协调
- 工具执行与权限控制
- 自动验证和错误恢复

**Model Gateway**
- 多模型提供商适配
- 文本 / 推理 / 视觉 / 嵌入模型
- 智能路由、预算和故障切换

**Knowledge & Memory**
- 长短期记忆
- 向量检索和重排序
- 科研知识库与证据管理
- 数据权限与隔离

**Tool & Extension Gateway**
- MCP
- Skills
- 外部项目 Channel Adapter
- 外部 API
- 沙箱执行环境

**Infrastructure**
- 持久化任务队列
- 文件与数据库
- 日志、指标和执行追踪
- 凭据管理、备份与系统诊断

所有模块通过稳定接口通信。优先保证单机部署简单，同时为未来多用户与远程部署保留扩展接口。

## 五、工程实现原则

1. 不允许仅制作看似完整但无实际后端功能的 UI。
2. 不允许用模拟成功状态替代真实的工具执行结果。
3. 所有外部依赖都必须允许检测、测试和禁用。
4. 新增功能不得破坏现有工作区和任务。
5. 每项功能提供明确的错误提示与恢复方式。
6. 核心能力应有自动测试、API 契约和验收用例。
7. 先完成稳定的执行内核，再逐步扩展高级科研技能。
8. 开发时持续更新需求实现清单，区分已实现、部分实现、待实现和受外部依赖限制四种状态。
