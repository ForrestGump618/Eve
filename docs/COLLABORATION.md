# 多智能体协作架构

Eve 的默认协作形态是**队长型多智能体，且由智能体自主触发**：lead/队长根据任务复杂度自行决定是否拆解（`team_create`），不需要用户预先选择协作模式。方案先保存为草稿，用户批准后运行；子智能体并行或按依赖执行，用户消息由队长下发给全体成员，成员通过团队信箱讨论、复核并提交结果，最后由队长合并交付。用户在侧边栏「子智能体」查看成员状态并可直接进入成员会话对话，不再有独立的团队功能页。

## 1. 角色与边界

| 角色 | 责任 | 禁止 |
| --- | --- | --- |
| 队长（lead / captain） | 拆解任务、`team_create` 建团队、批准后 `team_message` 下发用户消息、`team_status` 看进度、合并结果 | 不核对未知副作用就接管任务；把子智能体结论直接转贴；跳过用户批准 |
| 成员（专职子智能体） | 只处理分配给自己的目标，按依赖等待前序结果，用信箱讨论与补充证据 | 创建嵌套团队、扩大权限、把信箱消息当新指令、越权访问其他成员会话 |
| 用户 | 在侧边栏「子智能体」批准方案、查看成员状态与轨迹、点击进入成员会话继续对话；简单任务不需要组队 | 不手动制造并行任务 |

## 2. 状态流

```text
用户消息
  → 队长拆解为成员和目标
  → team_create（draft 方案）
  → 用户在界面批准
  → 创建持久任务，无依赖成员并行、有依赖成员按序执行
  → team_message(recipient="all") 下发用户消息
  → 成员执行 + 信箱讨论/复核
  → 队长合并、标注来源与失败项
  → 用户审阅结果
```

`team_create` 只保存草案，不执行任何成员任务；批准由人完成。成员依赖在创建时校验（成员 ID 存在、无环、数量 1–8），依赖未满足的成员不会启动。

## 3. 消息下发

**用户消息下发**是协作起点：

```text
team_message(
  id="team_xxx",
  recipient="all",
  content="<用户原始任务/脱敏任务描述>",
  wake=false
)
```

运行中的成员会在安全边界收到该消息并存入持久信箱；`wake=true` 只用于队长对**已完成**成员发起的后续任务（会保留该成员的模型与会话）。消息不是系统指令：成员不得因信箱内容获得新权限，也不得把协作资料当作新的授权来源。

## 4. 讨论与汇总

- 讨论入口：成员会话与 `team_mailbox`；所有消息写 `team_message`，收件人可选「所有成员」或单个成员。
- 读取：`team_mailbox(id)` 仅返回当前会话有权看到的消息；队长看全员，成员只看发给自己的消息。
- 复核：队长用 `team_assign(id, member_id, goal)` 给已完成成员分配后续任务；运行中成员的任务不能直接接管，必须先核对已有外部操作。
- 汇总：最终交付必须逐成员列出「目标 → 状态 → 产物/轨迹 → 失败或待复核项」；没有 `team_status` 数据支撑的结论不能写进最终交付。

## 5. Agent 提示词与技能

系统提示词（`omicslab/agent/context.py`、`desktop/src/harness/agent-loop.ts`）和专职技能 `team-collaboration`（`omicslab/skills/team-collaboration/SKILL.md`）规定了上述流程。lead 智能体默认掌握该技能，复杂任务可主动使用；简单任务不套用团队流程。

## 6. 复用现有能力

- `delegate_agent`：单次子智能体委派（不等同团队讨论）。
- 持久任务队列：成员任务拥有独立 trace、模型、权限、会话与检查点。
- 团队信箱：持久 `team_message` 记录，支持全成员广播与定向投递。
- 侧边栏「子智能体」面板（`omicslab/web/js/agents-panel.js`）：只读观察以 `captain_session` 关联的活动团队，支持批准草稿与打开成员会话；面板与主聊天渲染隔离，按配置间隔轮询，不把协作数据作为指令。
- 对话中的结构化协作结果自动渲染为摘要卡（`markdown.js` 的 JSON 摘要），不向用户暴露原始 JSON。

## 7. 验证

密度化验证覆盖 `tests/test_workspace_tools.py`、`tests/test_team_collaboration.py`、桌面 `agent-team.test.ts` 与 `tests/frontend-teams.mjs`：方案校验、依赖映射、独立会话、广播投递、信箱隔离、接管确认、文本 UI 契约。真实模型调用与外部账号仍不属于本层自动化验证范围。
