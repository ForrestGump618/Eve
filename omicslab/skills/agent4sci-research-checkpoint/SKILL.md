# Agent4Sci Research Checkpoint for Eve

这不是小时级后台任务，也不是第二套调度器。它在现有 durable run 的阶段节点和连续推进边界执行，用来发现“看起来很忙，但正在偏离问题”的状态，并立即完成可执行的纠偏动作。

## 触发时机

- 进入 `preregistration`、`analysis`、`experiment_design`、`figures` 前。
- 完成一个节点、准备调用 `wish_record` 前。
- 连续推进中，完成当前节点并准备进入下一个节点前。
- 长任务失败、重试、疑似卡住、资源不足或结果与预测冲突时。
- 准备改变主要终点、筛选规则、模型或研究路线时。

简单读取一个文件或执行一条确定性命令不需要走完整检查。

## Part 1：研究漂移

结合 `wish_status`、当前阶段产物和已有失败记录逐项判断：

- 是否只尝试了最安全、最熟悉的增量方案，而没有执行或解释高风险候选？
- 当前工作是在增加机制信息，还是只在调参数、换调度器、做集成或改框架？
- 是否因为一次失败就放弃，而没有定位数据、实现、资源或设计原因？
- 是否只展示成功结果，隐藏了失败、阴性或不支持假设的证据？
- 是否把“工程上能跑”误写成“科学上得到支持”？
- 剩余预算下，当前领先方案是否仍是最值得检验的解释？

出现漂移时，先重读章程、证据矩阵、预注册和真实日志，再决定继续、缩小问题或停止；不要把重写叙事当作纠偏。

## Part 2：真实运行状态

对每个正在运行或准备启动的任务核对：

- 执行位置是本地还是已批准的 SSH 主机，路径是否属于当前愿望工作区。
- CPU、GPU、内存、磁盘、队列和墙钟是否与任务需求匹配。
- 日志文件在哪里，最近更新时间、退出码、异常和截断情况。
- 真实产物、中间文件和数据行数是否存在；计划、mock、缓存和最终结果是否被区分。
- 子智能体或脚本生成的实现是否经过独立复核；是否存在硬编码答案、测试集泄漏或跳过失败。
- 高并发是否反而拖慢 I/O、模型调用或 CPU 预处理；是否需要排队、合并或降并发。

没有检查日志和产物时，不得说“任务正常运行”。

## Part 3：策略与预算

回答并记录：

- 已用和剩余的时间、模型调用、计算资源与关键依赖。
- 哪些主要终点尚未被检验；哪些失败会真正改变下一步。
- 是否有尚未追查的瓶颈，修复它是否比新增实验更有价值。
- 哪些候选可以停止、归档或降级；哪些外部条件需要用户授权。
- 当前证据支持继续、转向、补数据还是终止；相应停止规则是否已经满足。

若需要改变预注册的主要终点、排除规则或成功判据，保留原版本并创建带时间和理由的修订版，交用户或队长确认。不得覆盖旧判据后声称“原本如此”。

## Part 4：行动闭环

1. 从 Part 1–3 提取最多 5 个有负责人、有产物、有完成条件的行动项。
2. 在本轮完成能立即执行的检查、修复、重跑或证据补全。
3. 把检查摘要写入当前阶段主产物的 `## Research checkpoint` 小节；若当前阶段只有图表或多脚本，写入本阶段目录内的简短摘要文件。
4. 在 `wish_record` 前重查：主要主张是否有真实产物、失败是否有解释、预算是否仍允许、下一步是否有明确依赖。
5. 连续推进时，在下一个节点开始前重新检查；旧结论不得直接沿用。

不要粘贴完整日志、原始 JSON、表格转储或大段命令输出。只保留关键指标、错误指纹、产物路径和行动结论。

## 质量门禁

- [ ] 高风险方案已执行，或有基于证据的暂缓/终止理由。
- [ ] 当前工作改变的是机制、数据、设计或评测，而不只是界面包装。
- [ ] 所有失败和阴性结果都有原因、影响和下一步。
- [ ] 资源、时间、日志与产物经过实际核对。
- [ ] 子智能体实现已被复核，测试与数据划分没有被污染。
- [ ] 预注册变更有版本和理由，没有事后改写判据。
- [ ] 行动项已完成或在当前节点中明确阻塞，不只停留在清单。
- [ ] 没有把运行成功、测试通过或图表生成当作科学结论成立。

## 交接

- 统计与方法问题：`statistical-rigor`、`causal-inference`。
- 计算资源或远程主机：`remote-compute-ssh`、`function-registry`。
- 湿实验与读数解释：`experimental-design`、`wet-lab-experiment-design`、`wet-lab-result-interpretation`。
- 需要重新形成方案：回到 `agent4sci-research-ideation`，不要直接重做全部旧实验。
