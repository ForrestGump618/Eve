# Agent4Sci Research Ideation for Eve

把“提出一个好想法”改造成可核查的科研设计。目标不是堆叠流行方法，而是找到能改变当前证据状态、且能在现有工作区真实执行的实验或分析。

## 适用位置

- `scouting`：分别检索领域科学方法和计算/AI方法，记录可复用的数据、模型、评测与机制。
- `evidence_matrix`：把文献主张、适用条件、反证和项目内证据放到同一证据矩阵。
- `hypotheses`：输出有机制、可证伪、可比较的候选方案。
- `preregistration`：把选中的方案转成主要终点、判据、资源预算和停止规则。

不另建项目、任务或调度器。状态始终通过 `wish_status` 和当前愿望工作区恢复。

## 红线

1. 不得编造论文、DOI、PMID、数据集、基线分数或工具输出。没有检索到的内容写“未检索到”，并保留查询与日期。
2. 不得把超参数微调、调度器替换、简单集成或框架升级包装成“高风险创新”；除非有机制层面的新预测。
3. 不得先看结果再补假设或判据。预注册后的变化必须保留旧版本并新增修订版。
4. 不得把所有候选都做成浅层试验。一个阶段只深入少量可区分方案，其余写明暂不执行原因。
5. 不得假设当前主机具备某 GPU、软件或数据。资源结论必须来自工作区、`science_inspect`、`workspace_info` 或已批准的远程检查。

## 工作流

### 1. 恢复证据边界

先用 `wish_status` 读取当前节点、依赖、预算、阻塞和已登记产物；再读取 `charter.md`、已有证据矩阵和假设，避免重复已经否定的路线。只在必要时使用 `team_create` / `team_message` 拆出文献、数据和独立审查角色。

### 2. 建立两条文献线

优先使用 `database_search`、`web_search`，并读取用户投喂到工作区的论文；需要交叉来源时同时检查 PubMed/Europe PMC、OpenAlex、arXiv、bioRxiv 或 medRxiv（以当前工具实际覆盖为准）。每条记录至少保留：

- 题名、作者、年份、期刊或预印本平台、DOI/PMID/URL。
- 研究类型：原始研究、方法、综述、立场文章或基准报告。
- 与当前课题直接相关的机制、数据、模型、评测或失败模式。
- 可迁移到 Eve 的最小操作，以及明确不适用的条件。

领域线回答“这个系统为何会这样变化”；方法线回答“哪一种计算或实验设计能更好地区分解释”。两条线都为空时，停止提出看似具体的方案，转而登记文献缺口。

### 3. 生成候选方案

每个候选写在同一张表或同一组小卡中，避免散落的大段 JSON：

| 字段 | 内容 |
| --- | --- |
| ID 与层级 | `T1-*` 高风险高回报；`T2-*` 文献支持充分且可较快验证 |
| 机制链 | A → B → C，每步标注 established / plausible / speculative |
| 干预或比较 | 实际改变什么，与哪个基线比较 |
| 可观测预测 | 方向、幅度、时间窗和适用样本 |
| 主要指标 | 只设一个主要判据；次要指标列明比较族 |
| 证伪条件 | 什么结果会否定该方案，而不是“再调一调” |
| 文献依据 | 逐条对应检索记录，不写泛化引用 |
| 资源预算 | 数据、CPU/GPU、内存、墙钟、依赖与审批 |
| 风险与竞争解释 | 批次、混杂、实现错误、容量不足、选择效应 |

`Tier 1` 必须包含至少一种机制、表示、模型组件或实验范式的实质改变。`Tier 2` 可以是有文献支持的特征处理、统计设计、成熟模型替换或评测改进。若 `Tier 1` 本质仍是调参或集成，降为 `Tier 2` 并补一个真正的探索方案，或明确本阶段不提供 `Tier 1`。

### 4. 先做新颖性校准

逐项回答并在阶段产物中保留结论：

- 领域专家会认为这是一个真正不同的问题解释，还是熟悉方法换了说法？
- 该方案是否直接来自当前课题的瓶颈，而不是从热门论文反向拼接？
- 是否考虑了结构相似、但来自数学、物理、工程或计算机科学的迁移方法？
- 若方案失败，是否会留下关于机制、数据或设计的新信息？
- 当前数据与执行环境能否真正检验它？不能时，最小补齐条件是什么？

### 5. 排序但不伪装成确定分数

排序至少考虑机制特异性、证据支持、可证伪性、信息增益、可行性、资源成本和失败恢复。说明排序依据和不确定处，不输出伪精确的“科学价值 0.873”。优先执行能区分竞争解释的方案，而不是所有方案共享同一盲点的一组变体。

### 6. 写回现有节点

- 资源侦察：`evidence/scouting.md`
- 证据矩阵：`evidence/evidence-matrix.md`
- 假设与方案：`analysis/hypotheses.md`
- 预注册：`experiments/preregistration.md`

写清“已有证据 / 当前推断 / 仍未知 / 下一步行动”。不要把检索结果直接写成课题结论；不要粘贴长篇原始 JSON、工具日志或完整网页。

## 交接

- 需要统计设计时加载 `statistical-rigor`；需要湿实验或独立验证时加载 `experimental-design`、`wet-lab-experiment-design`。
- 进入预注册、分析、实验设计和图表前加载 `agent4sci-research-checkpoint`。
- 只有真实产物存在后才能用 `wish_record` 登记节点；模型不能代替用户完成最终复核。

## 完成检查

- [ ] 两条文献线都有真实来源，或明确记录缺口。
- [ ] 每个候选都有机制、预测、主要指标和证伪条件。
- [ ] `Tier 1` 没有被调参、集成或换框架冒充。
- [ ] 资源预算来自实际检查，不来自假设。
- [ ] 至少写出一条竞争解释及其区分办法。
- [ ] 输出已写入对应阶段产物，而不是只留在聊天中。
